# قواعد محاسبات مالی

## واحد پول
- کاربر **صریحاً** واحد فایل و واحد نمایش را انتخاب می‌کند (تومان/ریال). هیچ حدسی
  از بزرگی اعداد زده نمی‌شود.
- `۱ تومان = ۱۰ ریال` (منبع یگانه: `ingest/currency.py::_RIAL_PER_UNIT`).
- تحلیل‌های pandas روی **واحد نمایش** و با `float64` کار می‌کنند (رفتار فعلی، تست‌شده).
- دفتر کل canonical **عدد صحیح ریال** ذخیره می‌کند (`BigInteger`، نام `*_rial`).
  ریال خودش کوچک‌ترین واحد است، پس نام `minor_unit` گمراه‌کننده می‌بود.

## تبدیل در مرز نوشتن
```
value_rial = rint(value_display × rial_per_unit(display_currency))
```
- **تنها یک ضرب** انجام می‌شود، همیشه از فریم واحد-نمایش.
- گرد کردن: `np.rint` (نیم به زوج). `NaN → NULL` (هرگز صفر).
- مقدار منفی مجاز است (برگشت از فروش).
- `quantity` → `quantity_milli` (×۱۰۰۰) تا انبار صحیح بماند.
- تخفیف نسبتی → `discount_rate_bp` (پایه‌ی هزارم)، تخفیف مبلغی → `discount_rial`.
  تصمیم از `clean.attrs["discount_is_amount"]` می‌آید (یک‌بار در پاک‌سازی محاسبه شده).

## تلرانس آشتی
| سنجه | تلرانس |
|---|---|
| هر خط | ≤ ۱ ریال |
| هر batch | `max(1, ceil(n_lines / 2))` ریال |
| انحراف نسبی جمع‌ها | ≤ 1e-9 |
| شمارش‌ها (خط/سفارش/مشتری) | **صفر** |

منشأ انحراف: درآمدی که از `quantity × unit_price × (1 − نرخ تخفیف)` مشتق شده،
نه مبالغ مستقیم فایل (که عدد صحیح‌اند و دقیق تبدیل می‌شوند).

## سقف امن عددی
`int64` تا ~۹.۲e۱۸ ریال جا دارد. برای امنیت JSON (`Number.MAX_SAFE_INTEGER`)
سقف مستند ۹e۱۵ ریال است.

## تفکیک KPI (وضعیت فعلی، حفظ‌شده)
```
فروش ناخالص (gross_sales)  = جمع ردیف‌های مثبت
− برگشت از فروش (returns_total)
= فروش خالص (net_sales) ← سرخط «درآمد کل»
```
- فاکتوری که جمع خالصش مثبت نباشد **سفارش شمرده نمی‌شود**.
- تخفیف مبلغی جداگانه جمع می‌شود (`discount_total`)؛ تخفیف نسبتی جمع‌پذیر نیست.

## سود ناخالص — مسدود
داده‌ی بهای خرید/تمام‌شده **در دست نیست**. بنابراین:
- ستون‌های `cost_rial`, `cost_source`, `cost_confidence`, `margin_rial` ساخته
  می‌شوند ولی **NULL** می‌مانند. `margin_rial IS NULL` یعنی **نامعلوم**، نه صفر.
- **هیچ فیلد API یا برچسب UI عدد درآمدی را «سود» نمی‌نامد.** هر پاسخ پولی
  `economics_note_fa` دارد:
  > همه‌ی مبالغ «درآمد» هستند؛ بهای تمام‌شده در داده موجود نیست، بنابراین سود
  > ناخالص محاسبه نشده است.
- به‌محض رسیدن داده‌ی بهای خرید، همان زیرساخت فعال می‌شود.

## صداقت علّی
| فیلد | معنی | وضعیت |
|---|---|---|
| `value_rial` / `expected_value_rial` | ارزش فرصت (اگر مشتری خرید کند) | محاسبه می‌شود |
| `attributed_revenue_rial` | درآمد انتساب‌یافته بعد از اقدام | NULL تا ثبت exposure |
| `incremental_revenue_rial` | اثر افزوده‌ی علّی | **NULL تا وجود گروه کنترل** |
هیچ‌گاه عدد پیش‌بینی‌شده در فیلد افزوده نوشته نمی‌شود.

## باگ رفع‌شده در این ارتقا
تخفیف **مبلغی** پیش‌تر در `convert_monetary_columns` تبدیل نمی‌شد ولی `kpis.py`
آن را روی فریم تبدیل‌شده جمع می‌زد → وقتی واحد فایل ≠ واحد نمایش،
`discount_total` **۱۰ برابر** غلط بود. اکنون تبدیل با گارد
`attrs["discount_is_amount"]` انجام می‌شود.
